# مقارنة الهوية: المهارة مقابل النظام المرجعي

تاريخ الفحص: 21 سبتمبر 2026  
المراجع: لوحة `/mu/dashboard` في مشروع UEP + `docs/DESIGN.md` + `docs/design-package/tokens.css` + `src/index.css` + مكوّنات الهيكل والبطاقات.  
المهارة: `skills/saudi-soft/` (كل الملفات: `SKILL.md`، الجسر، الوصفات، القواعد، السكربتات، التقييمات).

هذا الملف تقرير داخلي. عند تنفيذ الخطة على ملفات المهارة **لا يُذكر اسم الجهة ولا مسار المشروع المرجعي** — المهارة تبقى هوية سعودية مستقلة قابلة للنشر.

---

## 1) الخلاصة

المهارة نسخت **لوحة الألوان ونصف القطر والخط** بدقة عالية. ما لم تنسخه هو **نظام التركيب**: مقاسات الهيكل، تدرجات البطاقات، إيقاع النصوص، كبسولة الثيم/اللغة، ووصفات الصفحة. لذلك الوكيل يبني تطبيقًا «أخضر Soft» يبدو كـ shadcn الافتراضي لا كلوحة الحرم.

| المقياس | النسبة |
| --- | ---: |
| تطابق ألوان الوضع الفاتح | **96%** |
| تطابق نصف القطر والخط الأساسي | **95%** |
| تطابق توكنز التخطيط (سايدبار/هيدر/فجوات) | **~10%** — غير معرّفة في المهارة |
| تطابق الشكل إذا اشتغل الوكيل بالمهارة وحدها | **~42%** |
| تطابق الهوية الكاملة (لون + مقاس + UX + تخطيط) | **~42%** |
| الهدف بعد تنفيذ هذه الخطة (بدون إضافة شيء غير موجود في المرجع) | **~90%** |

سبب الـ 42%: التوكنز موجودة في CSS، لكن التعليمات تدفع الوكيل لبطاقة shadcn الافتراضية (`CardHeader` + `CardTitle` بحجم 24px وحشوة 24px، بلا تدرج). هذا يطابق شكواك حرفياً: بطاقات كبيرة، نصوص غير مرتبة، بلا تدرج، الشكل غير احترافي.

## 2) ماذا تستطيع المهارة اليوم؟

تعمل بشكل صحيح:

- اللون الأساسي `#1B8354` والـ hover `#166A45` عبر متغيرات CSS — ليس `bg-green-*`.
- IBM Plex Sans Arabic كـ `--font-sans`.
- lucide فقط.
- RTL منطقياً (`ms` / `me` / `dir="rtl"`).
- وضع داكن عبر class `.dark` وتدوير التوكنز.
- حقن الجسر بـ `apply-theme.js`.
- مكوّنات shadcn الاحترافية (نماذج Field، حوارات، جداول، شات).
- نصف قطر: أزرار 10px، بطاقات 12px.

لا تعمل بالمستوى المرجعي (ما لم تعطِ الوكيل مسار المشروع المرجعي يدوياً):

- سايدبار بنفس العرض والعنصر النشط.
- هيدر 64px مع كبسولة الثيم وكبسولة اللغة.
- بطاقة إحصائية متدرجة ومضغوطة.
- بطاقة وصول سريع (أيقونة 40px + عنوان + وصف + شيفرون).
- عنوان صفحة مع بلاطة أيقونة 48px.
- شبكة 1→2→3 مع تمديد الصف الأخير.
- Utilities للتدرج والنص المتدرج والظلال المسماة.

خلاصة الألوان الفاتحة: **متطابقة تقريباً (96%)**. الفرق التشغيلي ليس الهكس، بل **أسماء الكلاسات** التي يكتبها الوكيل.

### 3.2 الألوان (وضع داكن)

**ليست نسخة حرفية.** المرجع يقلب السلم بـ HSL. المهارة تضع هكس تقريبية.

| | المرجع (HSL → تقريباً) | المهارة |
| --- | --- | --- |
| SA-600 داكن | `152.9 70% 45%` ≈ `#22B86A` | `#3DAF6E` |
| سطح البطاقة | `220 36.6% 6%` ≈ `#0A1018` | `#0B1220` |
| Canvas | `220 30% 8%` ≈ `#0E141F` | `#0F1724` |

قريبة بصرياً، ليست 100%. النسبة التقديرية للداكن: **~75%**.

### 3.3 نصف القطر

**متطابق:** sm 8 · md 10 · lg/xl 12 · 2xl 16 · full.

### 3.4 الخط

**متطابق في الأساسي:** IBM Plex Sans Arabic 400–700 + Work Sans احتياطي لاتيني.

**ناقص في المهارة (موجود في المرجع):**

- سلم العرض: 72 / 60 / 48 / 36 / 30 / 24.
- سلم النص: 20/30 · 18/28 · 16/24 · 14/20 · 12/18 · 10/14.
- أدوار مطبّقة: عنوان صفحة 24→30px bold · عنوان قسم بطاقة **16px** (المرجع يتجاوز `CardTitle` الافتراضي 24px) · جسم 14px · ميكرو 12px · تسمية مجموعة سايدبار 10px uppercase.
- Lora و Cairo موسمية — لا تُضاف كهوية يومية.

### 3.5 التخطيط — غير محدد في المهارة

هذه القيم **محددة في المرجع وغير موجودة** في جسر المهارة ولا في الوصفات:

| التوكن | القيمة المرجعية |
| --- | --- |
| عرض السايدبار | **280px** (مطوي **72px**) |
| ارتفاع الهيدر | **64px** |
| حشوة المحتوى | 16px، و24px من `md` |
| فجوة الشبكة | 16px (`gap-4`) |
| عنصر تنقل | `px-3 py-2` · نصف قطر 8px · أيقونة 16px |
| مؤشر العنصر النشط | شريط 3×24px، `rounded-full`، لون primary |
| خلفية العنصر النشط | `#F3FCF6` ونص `#166A45` |
| فاصل السايدبار/الصفحة | `border-e border-border/30` |
| بلاطة الشعار | 32×32 · `rounded-lg` · `bg-primary` |
| هدف لمس | 44×44 تحت 1024px |

### 3.6 التدرجات والظلال

الجسر فيه `--gradient-1` و `--gradient-2` و `--shadow-e1…e4`.

**ناقص:**

- كلاسات `.bg-gradient-1` / `.bg-gradient-2` / `.bg-gradient-brand` / `.text-gradient`.
- `--gradient-mesh` و `.bg-mesh` (خلفية خفيفة للاندنج، ليست زخرفة جديدة).
- `--shadow-e5` و `--shadow-e6`.
- ربط الظلال في `@theme` حتى يعمل `shadow-e1` في Tailwind v4. حالياً المتغيرات موجودة والكلاس **لا يُولَّد**.
- `--blur-md: 16px` لأغطية الحوارات.

### 3.7 البطاقات — هل الحجم محدد في المهارة؟

**غير محدد.** المهارة تقول «بطاقة + تسمية مكتومة + رقم عريض» أو «StatWidget محلي اختياري». لا ارتفاع، لا حشوة، لا تدرج، لا تسلسل نص.

المرجع يحدد نوعين (كلاهما مطلوب حسب الصفحة، لا نوع ثالث):

**أ) بطاقة إحصائية متدرجة** (`Stat variant="gradient"`) — هذه التي في لوحة `/mu/dashboard`:

- حشوة افتراضية **24px** (`p-6`)، مضغوط **16px** (`size="sm"`).
- نصف قطر **12px** (`rounded-xl`).
- الخلفية: `bg-gradient-to-br from-primary/10 to-transparent`.
- حد: `border-primary/10`.
- التسمية: `text-sm font-medium text-muted-foreground`.
- القيمة: **`text-3xl font-bold`**.
- التغيير: شريحة `rounded-full` بحجم `text-sm` + وصف `text-xs muted`.
- الأيقونة: 20px مكتومة بجانب التسمية.
- لا `CardTitle` 24px.

**ب) بطاقة إحصائية مضغوطة** (`StatWidget`) — لوحات الأدوار الأخرى:

- حشوة **16px** (`p-4`).
- القيمة `text-2xl font-bold`.
- التسمية `text-sm muted`.
- صندوق أيقونة **~48px** (`p-3 rounded-lg` + ت Tint `token/10`).
- hover: `shadow-lg` + `-translate-y-0.5`.

**ج) بطاقة وصول سريع** (صف الإجراءات في لوحة الحرم):

- `p-5` · `rounded-xl` · حد عادي.
- hover: `border-primary/40` + `bg-primary/5`.
- بلاطة أيقونة **40×40** `rounded-lg bg-primary/10 text-primary`.
- عنوان `font-semibold` ثم وصف `text-sm muted`.
- شيفرون يظهر عند الـ hover، اتجاهه منطقي مع RTL.

**د) بطاقة قسم** (محتوى، ليس KPI):

- نصف قطر 12px · حد + `shadow-e1` · حشوة رأس 24px.
- عنوان القسم يُخفَّض إلى **`text-base` (16px)** لا 24px الافتراضي.
- هذا أهم سبب لبطاقاتك «الكبيرة غير المنظمة»: الوكيل يستخدم `CardTitle` الافتراضي 24px لعنوان صغير داخل بطاقة.

## 4) الهيكل: هل المهارة ستضع نفس الشيء؟

السؤال: إذا فتحت لوحة جديدة بالمهارة، هل تخرج كلوحة الحرم؟

| العنصر في لوحة الحرم | هل المهارة تفرضه؟ | ماذا سيحدث اليوم |
| --- | --- | --- |
| سايدبار 280/72، عنصر نشط بشريط 3px وخلفية SA-50 | لا | shadcn Sidebar بعرض **256px** غالباً، بدون الشريط النشط ولا التسمية 10px |
| هيدر ثابت 64px، فاصل `border-border/30` | لا | الهيدر غير موصوف. الوكيل يخترع شريطًا أو لا يضعه |
| كبسولة الثيم: دائرة 28px، `bg-muted/50`، النشط `bg-background ring-2 ring-primary` | لا | `next-themes` فقط. الزر لن يكون بنفس الكبسولة |
| زر اللغة (أيقونة Languages، ghost، 40px) | لا | غير مذكور |
| بحث وسط الهيدر `bg-muted/50 rounded-lg` + ⌘K | لا | غير مذكور |
| تدرج لوني على بطاقات الإحصاء | لا — بل **ممنوع عملياً** لأن `styling.md` يقول: `className` للتخطيط فقط ولا تتجاوز ألوان المكوّن | بطاقة بيضاء مسطحة |
| عنوان الصفحة مع بلاطة 48px `bg-primary/10` | لا | `h1` عادي أو `CardTitle` ضخم |
| شبكة 1→2→3 وتمديد آخر صف | لا | `grid-cols-3` ثابت أو عشوائي |
| `text-gradient` على عناوين الترحيب | التوكن موجود، الكلاس غير موجود، الوصفة غير موجودة | عنوان بلون foreground فقط |
| كبسولة تنقل سفلية عائمة (موبايل) | لا | غير مذكور — لا تُخترع في المهارة كزخرفة؛ إن بُنيت لوحة تطبيق تُنسخ المواصفات أدناه فقط |

تبديل مساحة العمل (تسميات منتج معيّن) **خاص بالمرجع ولا يُنسخ للمهارة**. نمط الكبسولة المقسّمة نفسه ( pill مجزأة، النشط بحلقة primary ) يُنسخ كـ «Segmented capsule» عام لأي خيارين: ثيم، لغة، وضع عرض.

## 6) جذر المشكلة في تعليمات المهارة

ليست التوكنز. ثلاثة تعليمات تصنع الشكل السيئ:

1. **`rules/styling.md`**: «`className` للتخطيط لا للتنسيق» + «لا تتجاوز ألوان/طباعة المكوّن». هذا يمنع التدرج `from-primary/10` والحشوة المضغوطة `p-4` على البطاقة إن عُدّت تنسيقاً، ويمنع تخفيض `CardTitle` إلى `text-base`.
2. **`rules/composition.md` + `evals/evals.json` رقم 3**: يفرضان `CardHeader` + `CardTitle` + `CardContent` على بطاقة الداشبورد. `CardTitle` الافتراضي **24px**. في المرجع عنوان القسم **16px** والقيمة الإحصائية 24 أو 30px بدون `CardTitle`.
3. **`references/recipes.md`**: يقول «Dashboard = Sidebar + Card + Chart + Table» و«ثلاث بطاقات إحصائية» بلا مقاس ولا تدرج. الوكيل يرتجل shadcn الافتراضي.

النتيجة: ألوان صحيحة + تكوين خاطئ = منتج يبدو هاوياً.

## 7) خطة الإصلاح (بدون حذف ملفات، بدون اختراع بصري)

قيود التنفيذ:

- لا حذف لأي ملف موجود في `skills/saudi-soft/`.
- لا ذكر لاسم الجهة ولا لمسار المشروع داخل ملفات المهارة.
- لا إضافة نمط غير موجود في المرجع (لا ذهب، لا ظلال زجاجية جديدة، لا شبكة 4 أعمدة كأساس، لا أيقونات غير lucide).
- لا استبدال shadcn. نبقى عليه ونضبط الهوية بالتوكنز + الوصفات + كلاسات الجسر.

### المرحلة 0 — تنظيف المصدر من المهارة (قبل أي نشر)

- في `theme-bridge.css` و `identity.md`: احذف تعليقات المصدر وأسماء المنتجات.
- أبقِ الصياغة: «Soft identity / Saudi green / NDS-compatible tokens».

### المرحلة 1 — الجسر (`theme-bridge.css`) ثم مزامنة `identity.md`

أضف فقط ما هو حي في المرجع:

1. توكنز تخطيط: `--sidebar-width: 280px`، `--sidebar-collapsed-width: 72px`، `--topbar-height: 64px`.
2. Utilities التدرج: `.bg-gradient-1` `.bg-gradient-2` `.bg-gradient-brand` `.text-gradient`.
3. `.bg-mesh` من `--gradient-mesh` (نفس الصيغة المرجعية: ثلاث دوائر SA بشفافية 8–12%).
4. في `@theme inline`: `--shadow-e1…e4` (و e5/e6 كما في المرجع) حتى تعمل الكلاسات.
5. `--blur-md: 16px` وكلاس اختياري للـ overlay: `bg-foreground/40` + blur 16px (الحوارات، ليس الأدراج السفلية).
6. توكن دلالي للتسميات: `--label` = gray-700 `#384250`.
7. أسماء متوافقة: `--status-success/warning/info` = نفس `--success/warning/info` حتى تعمل `bg-status-success/10`.
8. إبقاء `--status-info-bg: #eff8ff` (أدق من نسخة المرجع الخاطئة `#ECFDF3`). سجّل القرار في `identity.md` بسطر واحد بدون ذكر المرجع.
9. لا تلمس primary/hover/radius/font — هي متطابقة.

### المرحلة 2 — وصفات التركيب (الملف الأهم)

وسّع `references/recipes.md` (لا تحذفه) بهذه الوصفات الإلزامية، بأمثلة shadcn فقط:

**هيكل التطبيق**

- `SidebarProvider` بعرض 280 / 72.
- عنصر نشط: `bg-primary/5` أو `bg-[--primary-subtle]` + نص primary-hover + شريط `before` 3×24 في `start`.
- `header` ثابت `h-16`، `bg-card`، `border-b border-border/30`.
- المحتوى: `pt-[var(--topbar-height)]` + `p-4 md:p-6`.
- كبسولة ثيم: حبة `rounded-full bg-muted/50 border-border/50`، زران شمس/قمر 28px، النشط `bg-background ring-2 ring-primary`.
- زر لغة: `Button variant="ghost" size="icon"` + أيقونة `Languages`.
- بحث الهيدر (سطح المكتب): `bg-muted/50 rounded-lg px-3 py-2 text-sm`.

**رأس الصفحة**

- بلاطة 48×48 `rounded-xl bg-primary/10 text-primary`.
- عنوان `text-2xl md:text-3xl font-bold tracking-tight`.
- وصف `text-sm md:text-base text-muted-foreground`.
- إجراءات `gap-2`.

**بطاقة إحصائية (KPI) — ليست CardTitle**

```
حشوة p-4 أو p-6 · rounded-xl
bg-gradient-to-br from-primary/10 to-transparent border-primary/10
صف: أيقونة 20px + تسمية text-sm muted
قيمة text-2xl أو text-3xl font-bold
صف سفلي: Badge/شريحة text-xs أو text-sm + وصف muted
hover: shadow-e4 -translate-y-0.5
عدد KPI في الصف: 3 أو 4 حسب الصفحة، شبكة gap-4، 2 أعمدة من sm
```

**بطاقة وصول / Hub**

- `p-5 rounded-xl border` · hover `border-primary/40 bg-primary/5`.
- أيقونة 40×40 `rounded-lg bg-primary/10`.
- عنوان semibold · وصف `text-sm muted`.
- ارتفاع الصف كامل `h-full`.
- شبكة: 1 / sm:2 / lg:3، والباقي 1 يمتد كامل العرض، الباقي 2 ينقسم 50/50.

**بطاقة قسم**

- يجوز `Card` كاملة.
- `CardTitle` يُمرَّر `className="text-base"` (16px) — هذا استثناء صريح لقاعدة «لا تتجاوز الطباعة».
- لا تستخدم `CardTitle` للرقم الإحصائي.

**أزرار**

- الافتراضي 40px / `text-sm` / hover عبر `--primary-hover`.
- فلاتر الصفحة: `size="sm"` + `rounded-full`، ليس Tabs.
- بحث: مكوّن بحث واحد (InputGroup أو wrapper)، لا حقل مخترع كل صفحة.

### المرحلة 3 — تعديل القواعد لا كسر shadcn

في `rules/styling.md` أضف استثناءات الهوية (وليس باباً مفتوحاً):

مسموح في `className`:

- حشوة/فجوة/شبكة (`p-4`، `gap-4`، `grid-cols-*`).
- تدرجات الهوية: `from-primary/10 to-transparent`، `bg-gradient-1/2`، `text-gradient`.
- Tint: `bg-primary/10`، `border-primary/10`، `hover:bg-primary/5`.
- تخفيض عنوان بطاقة القسم إلى `text-base`.
- رفع خفيف للبطاقة: `hover:-translate-y-0.5`.

ما يزال ممنوعاً:

- `bg-green-*` و hex في الكلاس.
- `dark:bg-*` للعلامة.
- أيقونات غير lucide.
- أنيميشن shimmer يدوي.

في `rules/composition.md`: بطاقة KPI ≠ بطاقة قسم. أزل الإلزام بـ CardTitle على الإحصائيات.

### المرحلة 4 — SKILL.md و Mode A

بعد `apply-theme.js`:

1. اربط الخط و `dir`.
2. ابنِ الهيكل (سايدبار + هيدر + كبسولة ثيم + لغة) من الوصفة، لا من الخيال.
3. أي لوحة تبدأ: رأس صفحة → صف إحصاء متدرج → شبكة محتوى.
4. `npx shadcn@latest docs` قبل كل مكوّن كما هو الآن.

حدّث جدول «Dashboard» من «Sidebar + Card + Chart + Table» إلى الوصفة أعلاه.

### المرحلة 5 — التقييمات

غيّر eval 3: بدل «Full Card composition» اطلب:

- تدرج `from-primary/10`.
- قيمة `text-2xl` أو `text-3xl` بدون `CardTitle`.
- تسمية `text-sm muted`.
- `gap-4`.
- هيكل هيدر 64px إن وُجدت لوحة كاملة.

أضف eval 5: لوحة عربية RTL فيها سايدبار 280، كبسولة ثيم مطابقة، ثلاث بطاقات متدرجة، بطاقتا hub.

لا تحذف التقييمات الحالية 1 و 2 و 4.

### المرحلة 6 — ما لا يُضاف

هذه خاصة بالمنتج المرجعي، ليست هوية قابلة لإعادة الاستخدام:

- مسميات مساحات العمل الخاصة.
- محتوى المواقف / الطاقة / الكليات / Blackboard.
- شريط وكيل عائم بتدرج كامل إلا إذا طلب المستخدم شريط تنقل موبايل — حينها تُنسخ مواصفات الكبسولة العائمة فقط بدون أيقونة وكيل.
- Gold / Lavender.
- Cairo كخط يومي.
- تدقيق الألوان `audit-colors.mjs` كبوابة بناء إلزامية في كل مشروع مستهلك (اختياري لاحقاً، ليس جزء الهوية البصرية).

## 9) تعريف «نفس الشكل» بعد الإصلاح

الوكيل على جهاز آخر، بدون مسار المشروع المرجعي، يجب أن ينتج:

2. سايدبار 280، عنصر نشط بشريط أخضر رفيع وخلفية SA-50.
3. هيدر 64px، كبسولة شمس/قمر بحلقة primary، زر لغة.
4. بطاقات إحصاء متدرجة من primary/10، رقم كبير، تسمية صغيرة، ليست صناديق `CardTitle` فارغة.
